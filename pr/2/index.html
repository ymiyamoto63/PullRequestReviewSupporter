#2 Rework PR summary for faster approve decisions

GitHub で PR を開く(差分・コミットの詳細)

判断サマリー

リスク高

PR サマリーを、リスク判断・変更前後の説明・コンポーネント図・レビュー観点を含む構成に刷新します。重要領域の変更はルールで検出し、Copilot CLI が利用できない場合も基本のレビュー情報を生成します。

GitHub Actions に Copilot CLI と追加のトークン設定を導入し、生成結果を公開ページに反映するため、権限・出力検証・失敗時の動作確認が必要です。

重要箇所の変更: 認証・認可、データベース、API、CI/CD・インフラ

Approve 前に確認すること

  • Copilot のトークンが必要最小限の権限で管理され、ログや生成 HTML に漏れないことを確認する。
  • Copilot が未設定・失敗・不正な出力の場合にも、ルールベースの情報を含むページが生成されることを確認する。
  • 認証・DB・API・秘密情報・依存関係・CI/CD の検出ルールが想定する変更を捕捉することを確認する。
  • 大きな差分を含む PR で、要約に必要な重要箇所が文字数上限で欠落しないことを確認する。
  • Actions の権限、トリガー、既存の GitHub Pages 公開フローに意図しない変更がないことを確認する。
  • 認証・認可への変更を確認する(下の「レビュー観点」参照)
  • データベースへの変更を確認する(下の「レビュー観点」参照)
  • APIへの変更を確認する(下の「レビュー観点」参照)

何を変更したか

目的: レビュー担当者が変更内容と確認すべきリスクを把握し、Approve の判断をより速く行えるようにするためです。

レビュー向けサマリーの生成

変更前PR の基本情報、変更規模、ファイル、コミット、差分などを並べ、変更内容や承認可否の判断は読み手に委ねていました。
→
変更後リスク度、Approve 前の確認事項、変更前後のカード、コンポーネント図、レビュー観点を含む HTML を生成します。
scripts/generate_pr_summary.py

重要変更のルール検出

変更前変更内容から注意すべき領域を列挙する明示的なルール定義はありませんでした。
→
変更後パスや差分の正規表現で認証・DB・API・秘密情報・依存関係・CI/CD の変更を検出し、該当する確認事項を必ず表示します。
scripts/review_rules.json scripts/generate_pr_summary.py

Copilot CLI による変更要約

変更前変更内容を構造化した要約として提示する仕組みはありませんでした。
→
変更後Copilot CLI に差分を渡して要約を生成し、結果を検証して HTML に反映します。未設定・失敗時もルール由来の観点と変更エリア図を出力します。
scripts/generate_pr_summary.py .github/workflows/pr-summary.yml README.md

Actions 設定と生成物の整理

変更前Copilot 用のインストール・設定がなく、Python キャッシュファイルが追跡対象に含まれていました。
→
変更後トークンが設定された場合に Copilot CLI を導入し、モデル設定を渡します。キャッシュ等を .gitignore に追加し、追跡されていた pyc を削除します。
