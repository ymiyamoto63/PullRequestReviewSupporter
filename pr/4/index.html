#4 Make the PR summary reusable from other repositories

GitHub で PR を開く(差分・コミットの詳細)

判断サマリー

リスク高

PR サマリー生成処理をコンポジットアクションとして切り出し、再利用可能ワークフローと直接利用の両方に対応します。Pages API から取得した公開 URL を PR コメントに使い、取得できない場合は従来の URL にフォールバックします。

呼び出し側に gh-pages への書き込みや PR コメント更新の権限を付与し、外部アクションを実行するため、権限設定と参照先の管理が重要です。

重要箇所の変更: 認証・認可、CI/CD・インフラ

Approve 前に確認すること

  • 導入先の GITHUB_TOKEN に gh-pages への書き込みと PR コメント更新の権限が許可されている。
  • フォーク由来の PR が実行対象外であり、想定外のトークン利用がない。
  • ルールファイルを指定した場合のチェックアウトと、未指定・不在時の既定ルールへのフォールバックが意図どおりである。
  • Pages API の URL と取得失敗時のリンク、および PR イベントごとのコメント更新が正しい。
  • アクションを @main で参照する運用リスクを許容できる、または参照固定の方針がある。
  • 認証・認可への変更を確認する(下の「レビュー観点」参照)

何を変更したか

目的: 他のリポジトリでも処理一式をコピーせず導入できるようにし、アクセス制御付き GitHub Pages でも正しいリンクを案内するためです。

処理をコンポジットアクション化

変更前PR サマリーの生成、gh-pages への公開、PR コメントの更新はこのリポジトリのワークフロー内に記述されていました。
→
変更後action.yml に処理をまとめ、他リポジトリからアクションとして利用できます。gh-pages は RUNNER_TEMP にチェックアウトし、スクリプトはアクション内から実行します。
action.yml

再利用可能ワークフローを追加

変更前他のリポジトリで利用するには、ワークフローやスクリプト、ルールをコピーする必要がありました。
→
変更後workflow_call で呼び出せるワークフローを追加し、モデル名や任意のルールファイルを指定できます。フォーク由来の PR は実行せず、公開とコメントに必要な権限・競合制御を設定します。
.github/workflows/pr-summary-reusable.yml

既存ワークフローをアクション利用に変更

変更前既存ワークフロー自身が生成・公開・コメントの各手順を実行していました。
→
変更後チェックアウト後に同じリポジトリのアクションを呼び出す構成になり、PR に含まれる action.yml を試せます。Pages URL 取得用の権限も追加されました。
.github/workflows/pr-summary.yml

Pages URL の取得とコメント更新を改善

変更前コメントの URL は owner/repo から組み立てられ、コメント手順は新規作成・再オープン時に限られていました。
→
変更後Pages API の URL を優先し、取得失敗時は従来の URL を使います。closed 以外のイベントでコメントを確認し、本文に変更がある場合だけ更新します。
action.yml

導入手順を文書化

変更前他のリポジトリや会社 Organization での利用方法の説明はありませんでした。
→
変更後再利用可能ワークフロー・直接利用の例、必要な権限や Pages 設定、Organization 内で使う場合の設定を説明します。
README.md
