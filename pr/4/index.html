#4 Make the PR summary reusable from other repositories

GitHub で PR を開く(差分・コミットの詳細)

判断サマリー

リスク高

PR のレビュー用サマリー生成をコンポジットアクションとして切り出し、再利用可能ワークフローと直接利用の両方に対応します。Pages API から公開 URL を取得して PR コメントに反映し、既存リンクの不要な更新を抑えます。

アクションが gh-pages への書き込みや PR コメント作成を行い、再利用ワークフローは可変な main ブランチのアクションを参照するため、権限設定と参照先の信頼性の確認が必要です。

重要箇所の変更: 認証・認可、CI/CD・インフラ

Approve 前に確認すること

  • 呼び出し側の contents: write、pull-requests: write、pages: read が必要最小限で設定されていること。
  • fork PR のガードが維持され、トークンを使う処理が不適切なイベントで実行されないこと。
  • Pages API の URL と取得失敗時のフォールバックが意図した公開先を指すこと。
  • rules 指定時のチェックアウトと、ファイルがない場合のフォールバックが正しく動作すること。
  • コメントが PR イベントごとに重複せず、内容に変更がある場合だけ更新されること。
  • 認証・認可への変更を確認する(下の「レビュー観点」参照)

何を変更したか

目的: サマリー生成のワークフローやスクリプトを他リポジトリへ複製せずに導入できるようにし、アクセス制御付き GitHub Pages でも正しいリンクを案内するためです。

サマリー生成をコンポジットアクション化

変更前生成、公開、コメントの処理はこのリポジトリのワークフローに直接記述されていました。
→
変更後action.yml に処理をまとめ、gh-pages を一時ディレクトリへ取得し、同梱スクリプトで生成・公開します。ルールファイルの指定も可能です。
action.yml

他リポジトリ向け再利用ワークフローを追加

変更前他リポジトリで使うにはワークフロー、スクリプト、ルールの複製が必要でした。
→
変更後再利用可能ワークフローからアクションを呼び出せます。fork PR のガード、必要な書き込み・Pages 読み取り権限、公開処理の concurrency 制御を設定します。
.github/workflows/pr-summary-reusable.yml

既存ワークフローをアクション利用に変更

変更前PR サマリー生成と公開の各ステップをワークフロー内に持っていました。
→
変更後リポジトリ内のアクションを呼び出し、PR ごとにその変更内容を使って実行します。Pages API 用の権限を追加しています。
.github/workflows/pr-summary.yml

コメント URL と更新動作を改善

変更前コメントの URL は github.io の既定形式で、コメント処理は作成・再オープン時に限られていました。
→
変更後Pages API が返す URL を優先し、取得失敗時は既定形式にフォールバックします。closed 以外のイベントで処理し、本文に変更がある場合だけ既存コメントを編集します。
action.yml

導入手順を README に追加

変更前他リポジトリや会社 Organization への導入手順は記載されていませんでした。
→
変更後再利用ワークフロー・直接利用の例、必要な権限や Secret、Organization 内で使う場合の設定を説明します。
README.md
