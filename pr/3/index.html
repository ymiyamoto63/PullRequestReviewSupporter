GitHub で PR を開く(差分・コミットの詳細)

判断サマリー

リスク中

検出ルールや AI 出力処理を確認するユニットテストを追加し、PR と main への push 時に GitHub Actions で実行します。キーワード検出ではテスト・文書・CI 設定などを除外するようにしました。

主な変更はテストと CI ですが、キーワード検出の除外条件が実際のレビュー対象ファイルまで除外しないか確認が必要です。

重要箇所の変更: CI/CD・インフラ

Approve 前に確認すること

  • 除外パターンが意図したファイルだけに適用されることを確認する
  • パス一致による重要箇所の検出が除外設定の影響を受けないことを確認する
  • ローカルで unittest が成功し、CI の PR・main push 条件が適切であることを確認する
  • AI 出力の不正値や Mermaid 図のラベル・エッジに関するテスト期待値が妥当であることを確認する

何を変更したか

目的: 要約生成スクリプトの重要な処理が変更時に壊れても気づけるよう、テストと自動実行の仕組みを整備します。

ユニットテストの追加

変更前検出ルール、AI 出力の解析・正規化、リスク判定、Mermaid 図の処理を確認するテストがありませんでした。
→
変更後標準ライブラリ unittest で各処理の代表的な挙動を検証します。
tests/test_generate_pr_summary.py

テストの自動実行

変更前PR や main への push でユニットテストを自動実行する CI がありませんでした。
→
変更後GitHub Actions が PR と main への push で unittest を実行します。
.github/workflows/test.yml

キーワード検出対象の除外

変更前テスト・文書・CI 設定にあるキーワードも内容によって検出対象になり得ました。
→
変更後設定した除外パスではキーワード検出を行わず、ルールのパス一致による検出は維持します。
scripts/generate_pr_summary.py scripts/review_rules.json

テスト手順の文書化

変更前README にテストの実行方法が記載されていませんでした。
→
変更後ローカルでの unittest 実行方法と CI の実行条件を記載します。
README.md
